# 表情发送：只同步编号，画面在本机播放

点击一个表情，发给服务器的是房间号、表情编号和本次消息的唯一编号。没有图片、帧图集或音频上传。对方收到编号后，使用本站统一缓存播放对应动画。

## 玩家看到什么

- 点击后自己的头像立即出现表情，不显示转圈或“发送中”。手机面板立即收起；冷却期间仍可正常操作牌桌。
- 服务器确认后，消息直接进入聊天记录，不必再等一次聊天查询。
- 同桌通过同一个房间订阅接收信号。斗地主将牌局与聊天合为 `/api/game/sync`，活跃阶段每秒最多一次，等待开局与局间每三秒一次；麻将和德州使用独立聊天订阅。所有订阅均串行执行，隐藏时暂停，失败时退避。仍是轮询，网络延迟存在，不承诺所有设备同时到达。
- 消息每人 3 秒最多一条表情，服务器继续检查冷却和成员权限。请求未结束前不并发发送新消息，防止重复点击堆积请求。
- 只有失败或结果不确定时才提示。超时后点击同一表情会复用原编号，服务器不会重复保存，本机也不会重复播放预览。
- 预览不算发送成功。明确失败会移除尚未确认的预览；如果轮询已确认消息，迟到的网络错误不会撤回已确认气泡。聊天记录只列服务器已确认的消息。

## 修改者要守住的边界

`lib/chat-send.ts` 只负责编号信号、立即预览和发送结果；不依赖素材下载或聊天刷新。`use-room-messages.ts` 是本房间唯一消息订阅，支持独立聊天或合并牌局传输；POST 回执直接交给它合并，三个游戏不要另写发送器。

POST 回执与 GET 订阅游标分开：例如自己的 102 号消息先确认，而朋友的 101 号消息还在路上，不能把订阅游标提前跳到 102，否则会丢掉朋友的气泡。

`clientId` 贯穿预览、服务器回执、轮询和气泡组件。它只代表一次发送，不是表情编号。回执只更新确认状态，保留原来的动画开始时间；同一表情第二次正常发送则使用新的消息编号。

首次进入、重连和回到前台只恢复历史记录。切房时取消原房间请求；图片和音效加载失败不能阻止发送、出牌或刷新消息。缓存机制见 [素材与缓存](motion-cache.md)。

## 验收入口

- `tests/unit/chat-signals.test.ts`：慢发送、信号体积、回执乱序、跨玩家消息不丢失、去重、失败和切房。
- `scripts/smoke-local.mjs`：正式产物的三个游戏都检查回执、幂等、成员权限、冷却及聊天不改牌局版本。
- 浏览器用测试账号实际发送，检查头像与聊天、冷却时鼠标、手机面板和后续选牌操作。
