# 运维：账号、配置和数据库

## 两套数据库

本地使用 `.wrangler/state`，线上使用当前 Sites 项目绑定的 D1。GitHub 只存源代码、公开素材和迁移，不存玩家、密码散列、房间数据或生产密钥。`config/local-db.json` 中的数据库 ID 是本地占位，不是线上数据库 ID。

数据库结构在 `db/schema.ts`，生成变更：

```bash
npm run db:generate
npm run db:local
```

第二步只应用本地迁移。提交 schema、追加的 SQL 和 `drizzle/meta/`；不要改已发布的 SQL，也不要把线上库导出来覆盖本地或反向覆盖。Sites 发布包会携带迁移，由平台应用。

## 环境变量与管理员

`.env.example` 说明需要的变量。普通玩家本地测试可以不配置；线上值由 Sites 管理。不要把真实 `.env`、Cookie 或临时 Sites 源码令牌提交到 GitHub。

- `ADMIN_USERNAME`：预留管理员用户名，当前线上是 MartinHamburger。
- `ADMIN_SETUP_HASH`：首次设置密钥的 SHA-256，不是管理员密码。
- 管理员首次通过 `/setup#key=一次性密钥` 自己设置密码。密钥由站点所有者生成并私下交付。
- 重设时由所有者生成新的 32 字节随机密钥，将其 SHA-256、到期毫秒时间戳、准确管理员账号 ID 分别设置为 `ADMIN_RESET_HASH`、`ADMIN_RESET_EXPIRES`、`ADMIN_RESET_USER_ID`。重设入口是 `/reset#key=一次性密钥`。建议 24 小时过期。
- 重设成功后，原会话全部注销，同一密钥不能重用。玩家记录和筹码保持不变。

本地管理员测试也应使用本地密钥和本地账号。不要复用线上的一次性链接；后端密码散列算法在 `lib/server.ts`。

## 常见故障

| 现象 | 先看什么 |
|---|---|
| 朋友进入站点遇到 blocked | 平台 / 网络访问层；先记录状态码，不要把它当成密码错误 |
| 页面能打开，但切游戏没反应 | 用正式构建重现，检查导航，不要仅检查页面 HTTP 200 |
| 动画慢 | 图鉴缓存进度、素材大小与内容指纹；见 [缓存框架](motion-cache.md) |
| 版本号冲突、提示牌桌已更新 | 先取新状态，不能绕过房间版本重发旧动作 |
| 全员离线时机器人不动 | 当前按在线成员请求推进，这是现有运行方式 |
| 管理员关闭正在进行的 ham 局 | 当前局杠分退款，之前已结束各局保留；不能直接删房间状态 |

后台列表有数量上限，系统面向小规模朋友局，尚未做大规模压力验证。需要扩大用户规模时，先单独评估同步、计时和数据库负载。

## 玩家反馈

顶部右侧“反馈中心”只允许已登录且未停用的账号提交纯文字。每个账号按北京时间日期最多成功保存 5 条，每条去掉首尾空白后最多 200 个 Unicode 字符；空白、控制字符、超长内容与跨站请求拒绝。数据库通过每日 5 个唯一名额在一次写入中限制并发；重试使用同一 `clientId`，不会重复保存或计次。接口另有每账号每分钟 30 次提交请求的保护，不影响每日成功额度。

管理员登录后在后台“玩家反馈”查看提交者、时间和内容，可刷新及分页加载。反馈不公开给其他玩家，文字按原文展示，不作为 HTML 执行。

- `GET /api/feedback`：本人当天的 `day`、`used`、`remaining`，不返回其他玩家内容。
- `POST /api/feedback`：JSON `{ "clientId": "UUID", "content": "建议内容" }`；成功返回反馈 `id` 与当天额度。
- `GET /api/admin/feedback`：仅管理员会话可读取，每页最多 50 条，返回 `items` 和 `next`；下一页传 `?before=<next>`。每条包含 `id`、`content`、`created`、`display`、`username`。

这些接口沿用现有登录会话，没有新增公开读取口或永久管理密钥。需要让 Codex 整理反馈时，由管理员授权使用当前已登录界面，或提供从该接口取得的反馈数据；不要把登录 Cookie、账号密码或线上凭据提交到仓库。
