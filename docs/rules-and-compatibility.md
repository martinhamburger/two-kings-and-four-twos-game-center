# 规则与兼容：新规则只进新房间

房间创建时保存规则快照。之后修改默认值，不会改正在玩的房间或过去的战报。不要改旧版本的含义，让旧引擎误解新状态。

## 当前默认值

| 游戏 | 当前版本 / 入口 | 重点 |
|---|---|---|
| 斗地主 | `landlord-v4`，`lib/game/engine.ts` | 三人；叫分后每人可加倍一次，所有人选择后才揭晓底牌并加入地主手牌。保存的 v2 和未标版本房间保留原有发牌及公开时机。地主和各农民逐笔计算，双方都加倍时该笔 ×4。建房可关闭个人加倍、炸弹加倍或春天加倍。 |
| 基础麻将 | `lib/mahjong/rules.ts` 的 BASIC | 四人 136 张，无花牌；吃碰杠；一人胡结束；新房间使用本桌筹码。旧积分房不追溯换算。 |
| ham 麻将 | `ham-v7`，`lib/mahjong/rules.ts` | 自摸通常 ×2；点炮本身 ×1。双赖子满足专门条件时，自摸与点炮的起点均为 ×4，再乘其他牌型。无门前清和无赖子加倍；七小对及豪华七对的最后进牌须代表 4～9 的万筒条。 |
| 德州扑克 | `holdem-v5`，`lib/holdem/engine.ts` | 4–10 座，默认初始 1000、前注 10、小盲 20、大盲 30；前注计入翻牌前已投入（跟到 30 合计投入 30）；完整加注幅度不得低于上次完整下注／加注，主动加注目标为前注倍数；正常结算全员亮底牌（含弃牌者）；允许局间补入并记录累计带入。 |

德州旧 `holdem-v1` 房间保留任意整数下注规则，`holdem-v2` 保留前注额外收取与前注倍数下注；新 v3 才将前注计入翻牌前下注。v3 前注不得高于小盲。当前新房间使用 v5，下注规则沿用 v3，正常结算后所有玩家亮底牌（含弃牌者）；五张以上才计算牌型，其他人弃牌获胜不补发公共牌，中止牌局不公开底牌。旧 v1–v4 保留原结算可见范围。此前保存的 v4 沿用前注计入下注，但允许任意增加至少 1 筹码均重新开放加注权。v1/v2/v3 保留各自原下注规则，均不回写规则快照或历史数据。

德州到时操作为服务端私有、带房间版本校验的选择，不向其他玩家公开，也不会在选择时扣款。仅在玩家自己的期限结束时执行仍合法的选择。跟注最多支付选择时确认的跟注金额；金额上涨或其他失效选择退回能过则过，否则弃牌。选择绑定手、街、本人已投入和剩余筹码，手动行动、换街/手即清理；页面恢复后提交清空，不从服务端恢复旧选择。已成功保存的方案不依赖浏览器倒计时执行。

ham 的双赖子仍要求胡前恰好两张赖子，与进牌组成同一副中张顺子，进牌代表 4–8。它不是“任意持有两张赖子就 ×4”。四赖直接胡是另一条规则，不共用双赖子排除自摸的逻辑。`ham-v5` 等老快照继续按原计算方式运行。

新 `ham-v7` 的七小对及全部豪华七对只限制最后胡进的一张，必须代表 4～9 的万、筒、条；其他手牌可以包含 1～3 和字牌。自摸、点炮与抢补杠一致；赖子和白板按最终代表身份判断。`ham-v6` 及更早房间和已保存的胡牌方案继续沿用原来的七对规则，不能在复原时补上新限制。

ham 普通胡中张限制、特殊牌型、严格禁用、奖牌和杠分的完整解释由 `lib/mahjong/rule-guide.ts`、`rules.ts`、`solver.ts` 和“本桌规则”共同维护。更改牌型时同步说明和测试，不能只改表格文字。

## 计分与隐私

- 斗地主带人机的对局不改变账号积分。新麻将和德州使用独立本桌筹码。
- 筹码存十进制字符串，计算用 `BigInt`，不要转为 `Number` 后相乘。
- ham 胡牌先确认方案，再由胡牌者逐张翻两张奖牌；公开接口不能提前返回奖牌。
- 斗地主、麻将结束后显示各人的剩余手牌；德州 v5 正常结束后全员亮底牌，旧 v1–v4 弃牌者底牌保持隐藏。
- 公开战报使用过滤后的只读快照，不能直接公开房间 JSON。

## 如何修改规则

1. 找到现有规则预设和快照读取位置。
2. 新增版本或明确兼容字段，保留旧版本分支。
3. 写新规则正反例，同时保留旧快照测试；涉及钱数时核验收支总和与重复提交。
4. 同步建房设置、“本桌规则”和战报说明。
5. 完成 [验收](testing.md) 后再提 PR。

若要回退发布，目标版本仍必须认识线上已经存在的新房间结构。数据库迁移只追加，不删除已经运行过的迁移。不能直接把支持新规则的服务回退到完全不认识该规则的引擎。

德州快捷加注的 1 倍等于服务端最低合法加注目标减当前本轮最高下注，随完整加注与当前房间规则变化，不再使用跟注额或固定大盲。按钮在输入金额上累加该幅度，至少从跟注额起算；遇到不足额全下形成的不整齐金额时，将加注目标向上取整到本桌下注单位。超出剩余筹码仍拒绝提交，不自动全下。

## 四人欢乐三打一试做

新房间单独保存 `landlord-four-v1`，普通三人 v4／v2、技能 v3 和未标版本房间均保留原行为。

- 两副牌 108 张，四位各 25 张、底牌 8 张；实例编号 0–107，重复牌面仍是不同手牌实例。一个地主、三个农民，任一农民先出完即农民共同获胜。
- 每人叫分一次、3 分立即确定地主，全员不叫重发。支持个人加倍，全部选择后公开并加入底牌；三家连续不出后原出牌者重新领出。
- 4–8 张同点数炸弹比张数再比点数；两个大王加两个小王为最大四王炸，同色王可组成普通对子。三带一对、飞机带不同点数对子；无三带一、飞机带单、四带二。
- 试做暂沿用本站计分开关：每次炸弹／四王炸 ×2，春天 ×2，每位农民与地主单独结算，地主承担三笔之和。地主加倍影响三笔，农民只影响自己一笔。公开底牌与炸弹倍数等待用户集中确认，不声称等同所有平台。
- 研究参考：[欢喜斗地主官方四人规则](https://ddz.qileyx.com/content/230458)、[边锋四人规则](https://www.gameabc.com/news/201901/4869.html)。两者共有发牌、阵营与炸弹层级；边锋底牌仅地主可见且炸弹计分与本站不同。普通 UI、原子提交、成员占座、人机、积分与历史继续使用既有框架，无数据迁移。

## 技能斗地主无人叫地主

新建技能房间保存 `noCallPolicy: dealer-free`：三家首次全不叫，由本局庄家免费成为地主，`bid` 与 `stake` 都为十进制字符串 `0`，不扣金币；底牌、地主首出、胜利点及装备效果照常。有人主动竞价仍按原价托管及退还。未保存此字段的旧房间继续按金币最多（并列按庄家起顺序）、托管 1 金币的规则，全桌无金币时才免费给庄家。不迁移旧房间与历史。
